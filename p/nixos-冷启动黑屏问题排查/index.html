NixOS 冷启动黑屏问题排查

2026-05-10

NixOS 冷启动黑屏问题排查

问题现象

  • 冷启动：在 systemd-boot 菜单选择最新 generation → 黑屏无任何输出 → 超时后自动重启回到 boot 菜单
  • 热切换：nixos-rebuild switch + systemctl restart display-manager → 一切正常，niri、网络、fcitx5 输入法均正常工作
  • 旧的 25.11 generation 冷启动正常

排查过程

日志缺失线索（锁定方向）

journalctl --list-boots 看不到任何失败启动的日志条目。

这意味内核在 systemd-journald 启动之前就崩溃了。 问题不在用户态（niri/GPU/Mesa），而在 initrd 阶段或更早的内核初始化阶段。

二进制对比（定位根因）

对比工作系统（25.11）和失败系统（26.05/unstable）的 /init 文件：

=== 25.11 (工作) ===
#! /nix/store/...-bash-interactive-5.3p3/bin/bash
（一个 bash 脚本）

=== 26.05/unstable (失败) ===
ELF  (一个 ELF 二进制文件)

进一步追溯到 /nix/store/.../nixos/modules/system/activation/top-level.nix 的生成逻辑：

if config.boot.initrd.enable && config.boot.initrd.systemd.enable then
    cp "$systemd/lib/systemd/systemd" $out/init   # <-- 直接使用 systemd 二进制
else
    cp ${config.system.build.bootStage2} $out/init  # <-- 使用 bash 脚本
fi

同时发现 systemd 版本从 258（25.11）升级到了 260（26.05/unstable）。

根因

NixOS 26.05/unstable 默认启用了 boot.initrd.systemd.enable（25.11 默认为 false），导致 /init 从 bash 脚本变成了 systemd 260 的 ELF 二进制文件。

systemd 260 作为 initrd 的 PID 1 在 ThinkPad X250 Broadwell 平台上崩溃，发生在 systemd-journald 启动之前，因此没有任何日志输出，屏幕黑屏，最终触发 watchdog 重启。

解决方案

在 configuration.nix 中添加一行配置，禁用 systemd-based initrd，回退到旧版 bash 脚本 init：

boot.initrd.systemd.enable = false;

最终配置变更

configuration.nix：

+ boot.initrd.systemd.enable = false;

总结

维度 说明
根本原因 NixOS 26.05 默认使用 systemd 260 作为 initrd PID 1，在 ThinkPad X250 上崩溃
为何难以排查 崩溃发生在 journald 启动前，无任何日志
最终修复 boot.initrd.systemd.enable = false，回退到 bash 脚本 init
修复行数 1 行配置
